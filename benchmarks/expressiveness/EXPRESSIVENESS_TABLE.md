## How to read the columns

### LOC (`ask/py/ls/pe/pf/bt`)

Non-comment lines between `CHECK_START` and `CHECK_END` in each framework port (full inlined check logic, not shared helpers). Order: **ask** = agent_spec_kit, **py** = pytest_plain, **ls** = langsmith, **pe** = pydantic_evals, **pf** = promptfoo, **bt** = braintrust. **`—`** means no port for that check in that framework.

### Failure specificity (`ask/py/ls/pe/pf/bt`)

Same order as LOC. Each letter is the **expected diagnostic quality** when that check fails on an intentional negative fixture (not pass/fail on golden traces). Lower letters mean harder debugging for operators.

| Grade | Meaning |
| --- | --- |
| **A** | Exact JSON/path witness with expected vs actual (e.g. matcher counterexample at `result.severity`) Example: `path=$[1] code=missing_element expected=... actual=... (tool/field witness)` |
| **B** | Names the violated rule, tool, or arg/result slice in plain text (no structured path) Example: `get_line_status.args.line_id expected 'LINE-001', got 'LINE-002'  OR  {'key': 'tool_args', 'score': 0}` |
| **C** | Named evaluator/scorer key or check category only (e.g. score 0 dict), no tool/field witness Example: `(no pure C-grade capture in this harness)` |
| **D** | Generic assertion or scorer failure (e.g. `AssertionError`, `score 0`, validation error class) Example: `AssertionError  OR  assertion returned False` |
| **E** | Opaque pass/fail boolean with no diagnostic detail Example: `(no E-grade capture in this harness)` |

Grades are **manually** assigned from captured messages — see [`MANUAL_FAILURE_CLASSIFICATION.md`](MANUAL_FAILURE_CLASSIFICATION.md) (not keyword auto-scoring). Messages: [`failures_samples.yaml`](failures_samples.yaml).
