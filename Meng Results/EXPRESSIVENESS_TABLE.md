## How to read the columns

### LOC (`ask/py/ls/pe/pf/bt`)

Non-comment lines between `CHECK_START` and `CHECK_END` in each framework port (full inlined check logic, not shared helpers). Order: **ask** = agent_spec_kit, **py** = pytest_plain, **ls** = langsmith, **pe** = pydantic_evals, **pf** = promptfoo, **bt** = braintrust. **`—`** means no port for that check in that framework.

### Failure specificity (`ask/py/ls/pe/pf/bt`)

Same order as LOC. Each letter is the **expected diagnostic quality** when that check fails on an intentional negative fixture (not pass/fail on golden traces). Lower letters mean harder debugging for operators.

| Grade | Meaning |
| --- | --- |
| **A** | Exact JSON/path witness with expected vs actual (e.g. matcher counterexample at `result.severity`) Example: `path=$[1] code=missing_element expected='expected value to appear after the previous match' actual="[{'name': 'authenticate_customer', 'args': {}, 'result': 'ok'}, {'name': 'get_line_status', 'args': {'line_id': 'LINE...` |
| **B** | Names the violated rule, tool, or arg/result slice in plain text (no structured path) Example: `get_line_status.args.line_id expected 'LINE-001', got 'LINE-002'` |
| **C** | Turn, step, or span index only (which step failed, not which field) Example: `assert False (sequence branch; no field path)` |
| **D** | Generic assertion or scorer failure (e.g. `AssertionError`, `score 0`, validation error class) Example: `AssertionError` |
| **E** | Opaque pass/fail boolean with no diagnostic detail Example: `False (no captured E-grade specimen in this harness)` |

Grades are assigned per (check, framework) in `catalog.py` from captured fail-trace runs (`scripts/collect_failure_samples.py`). Full matrix: [`failures_samples.yaml`](failures_samples.yaml) and [`FAILURE_SAMPLES.md`](FAILURE_SAMPLES.md).
