\begin{abstract}
Tool-using language-model agents can produce plausible replies while skipping authentication, calling the wrong tool, or leaving application state incorrect. Existing evaluation libraries support output grading, but multi-turn checks over replies, tool traces, and state often require separate datasets, graders, and custom code.

This project develops \emph{agent-spec-kit}, a framework for writing agent evaluations as executable conversation scenarios. Each scenario contains user turns, reply and tool assertions after each turn, and state postconditions. Failed assertions produce structured counterexamples that identify the requirement, dialogue turn, and nested value path that differed. The framework also supports repeated execution, user simulation, transcript mutation, failure shrinking, and extraction of discovered failures into fixed regression scenarios.

The evaluation uses TelcoSupportBench, a synthetic mobile-support domain containing fifty tasks and a reference LangGraph agent. \emph{agent-spec-kit} is compared with seven other evaluation approaches on authoring effort, clarity, failure specificity, injected-fault detection, and generative discovery. In the baseline run, all fifty output lanes passed, while twenty trace lanes and ten state lanes failed. In the twelve expressiveness specimens, \emph{agent-spec-kit} used 165 lines of check logic and received the highest clarity grade on every specimen. Full oracles detected tool and state faults missed by narrower lanes, and simulation and mutation fuzzing reached failure signatures absent from the manual scripts. These results show that agent evaluations benefit from combining reply, trace, and state oracles in one executable scenario, with failure reports precise enough to support regression testing.
\end{abstract}
