\section{Fault detection across oracle lanes}
\label{sec:fault-detection}

The third study asks whether split oracles (O, S, T, F) detect injected agent faults that a single output grade would miss. Ten fault families (F01--F10) mutate the reference agent or its prompts: premature escalation, wrong line or customer binding, unsupported credit, authentication and privacy leaks, wrong nested specialist child order, conditional structured-output violations, missing clarification before mutation, missing audit notes, failure to act when required, and wrong issue binding after user correction. Each family is run on a fixed set of task--oracle pairs where the initial baseline run had passed (Table~\ref{tab:baseline-initial}), so the denominator measures detection of the injection, not general agent quality.

Detection means the fault scenario fails the eligible oracle. Table~\ref{tab:fault-detection-summary} gives detection rates by fault family and lane. One hundred and fifty-two fault scenarios were parsed from the primary matrix run. Listing~\ref{lst:fault-detection-trace} shows a trace-lane counterexample from the injected wrong-line fault (detected on task T29).

Trace and full lanes account for most detections on ordering, binding, and clarification injections; output and state lanes are often near zero on the same families because the reply can stay plausible while tools or the store are wrong. Sparse cells in the summary (dashes) mean no eligible baseline pass for that lane, not a missing injection. The task-by-task grid is in Appendix~\ref{app:fault-detection-grid}.

Together with Section~\ref{sec:diagnostic-quality-faults}, the results treat split oracles as complementary witnesses on the same policy, not redundant grades.
